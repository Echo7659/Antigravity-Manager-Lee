# 仪表盘配额与推荐

配额页区分三个指标：5 小时窗口、周窗口，以及用于保护与推荐的综合剩余比例。综合值取已知的模型配额和时间窗口中较低者，采用保守的向下取整。它不是把不同套餐的 token 容量相加所得的余额。

例如，同一账号的 5 小时额度为 92%，周额度为 15%，综合值为 15%。账号列表的 5H 视图显示 92%，并补充周额度和综合值；当前账号卡片显示综合值，同时列出两个窗口。整个仪表盘显示所选账号池中已知数据的等权平均，未知窗口显示为“—”，不当作零，也不在可用账号为空时回退到禁用账号。

Gemini 和 Claude 独立推荐、独立切换，避免跨模型直接比较百分比。推荐排除异常、停用、限流及受额度保护的账号；配额相同时优先保留当前账号。切换期间显示处理中状态并禁止重复提交，服务端当前账号核对成功后才显示成功；错误及确认失败会明确显示。

当前账号切换不会改变整个账号池的平均值，也不会把反代轮询改成固定单账号。后台配额刷新会同步更新当前账号卡片；旧的当前账号请求不会覆盖已确认的新选择。

验证：`npm run test:dashboard`，覆盖窗口差异、未知数据、保护边界、推荐筛选、确认失败、旧响应乱序和当前卡片刷新。镜像构建在前端阶段运行这些测试。
