# 账号失败重试

从 `v4.7.1-lee.2` 起，一次生成请求首次失败后，最多再切换五个不同账号，总计最多六个账号。任何一次成功即返回。

| 场景 | 行为 |
| --- | --- |
| 上游返回 HTTP 400–599 | 按排除名单切换账号，最多六个不同账号 |
| 所有尝试失败 | 返回最近一次实际失败的状态码和错误信息 |
| 可用账号不足六个 | 尝试完可用账号后返回最后的实际失败，选号失败不覆盖它 |
| 本地鉴权或请求格式校验失败 | 直接返回，本地没有可供账号切换解决的上游请求 |
| 已向客户端交付的流式内容发生错误 | 通过流式错误事件结束，不整体重放已经交付的内容 |

账号排除名单只属于当前请求。固定账号、会话绑定、缓存优先及图片排队均不能重新选中该请求已使用的账号。请求内部不再使用 Grace Retry 在原账号重试。图片批量生成的每张图片分别计算六个账号的上限；供应商转发通道不经过这个 Google 账号池。

换号间隔按 200、400、800、1600、2000 毫秒递增；最后一次失败不再等待。429 的账号模型冷却继续记录上游 Retry-After 等信息，Gemini 原生接口也写入冷却记录。更换到其他可用账号不必等待失败账号的冷却结束。这个策略不代表请求会遍历全部账号，也不是全账号池的负载均衡改造。

普通 400 也按此策略重试，因此确定的参数错误可能连续失败六次；换号不能修正非法参数。流式断开、网络问题及现有的空响应检测，只有在处理器尚未交付响应时才可以换号。上游客户端保留同账号的服务端点回退，因此网络调用次数不等于不同账号数。

验证包括实际源码的请求、用量、流式及六账号边界测试，以及完整后端镜像构建。线上部署另行验证实际接口、账号保留和容器镜像摘要。
