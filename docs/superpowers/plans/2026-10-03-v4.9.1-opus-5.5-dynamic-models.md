# Antigravity Manager 4.9.1、Opus 5.5 与动态模型目录 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留 Lee 版账号调度、配额保护和 token/成本统计的前提下同步上游 v4.9.1，支持 Claude Opus 5.5，并使新旧模型随 Google 目录自动上下线。

**Architecture:** 从 Lee `main` 合并精确上游标签 `v4.9.1`，冲突解决同时保留上游新结构和 Lee 行为不变式。动态目录复用账号 JSON 中已有的 `quota.models` 与 `quota.last_updated`：汇总 24 小时内的新鲜快照，无新鲜快照时回退到最新历史成功快照。后端产生唯一目录，API、前端和集成共用该结果。

**Tech Stack:** Rust 2024/Tauri 2/Axum/Rusqlite, TypeScript 5.8/React 19/Zustand, Docker BuildKit, GitHub Actions, GHCR, Docker Compose.

## Global Constraints

- 上游基线必须是精确标签 `v4.9.1`（`6a360c3a1d54bb2385818a3ebb05579832735cee`）。
- 单次生成请求最多尝试 6 个不同账号；同一请求不得重用失败账号。
- 保留配额保护、账号排名、周配额预留、首响应超时、代理绑定热更新和健康检查错峰。
- 详细日志关闭时仍必须记录 token 和成本统计。
- 模型快照新鲜期固定为 24 小时（`86_400` 秒）；无新鲜快照时使用最新历史成功快照。
- 不新增外部数据库、定时任务服务或新运行时依赖。
- Opus 5.5 仅可调度 Ultra 或 `loadCodeAssist.paidTier` 明确识别的付费 Pro；试用 Pro 不可用。
- Opus 5.5 使用 adaptive thinking，不得发送关闭 thinking 或手工 thinking budget。
- 部署只使用 GitHub 上 CI 通过的精确 commit 和 GHCR digest。
- 不删除或重建生产账号、凭据、SQLite 统计库、代理绑定或配置。
