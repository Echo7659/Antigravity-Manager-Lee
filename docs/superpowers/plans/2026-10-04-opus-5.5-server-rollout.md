# Opus 5.5 Server Rollout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在纯 Linux/Web 架构上完成 Opus 5.5 资格调度、adaptive thinking、成本统计、发布和生产部署。

**Architecture:** 动态模型目录继续来自 24 小时新鲜 Google 账号快照。账号 JSON 持久化 `loadCodeAssist.paidTier` 的可选证据；Opus 5.5 在进入既有排序和六账号重试前过滤资格，协议 mapper 强制 adaptive thinking，统计模块按模型计价。

**Tech Stack:** Rust 1.96 edition 2024, Axum, Tokio, React 19, Docker BuildKit, GitHub Actions, GHCR, Docker Compose.

## Global Constraints

- 消费 `2026-10-04-linux-web-core-simplification.md` 的已审查完成结果。
- 上游基线必须包含精确 `v4.9.1` commit `6a360c3a1d54bb2385818a3ebb05579832735cee`。
- 单次生成请求最多尝试 6 个不同账号；同一请求不得重用失败账号。
- 保留配额保护、账号排名、周配额预留、首响应超时、代理绑定热更新和健康检查错峰。
- 详细日志关闭时仍必须记录 Token 和成本统计。
- 模型目录新鲜期固定 86,400 秒；无新鲜快照时使用最新历史成功目录快照。
- Opus 5.5 仅可调度 Ultra 或 `loadCodeAssist.paidTier` 明确识别的付费 Pro；试用 Pro 不可用。
- Opus 5.5 使用 adaptive thinking，不发送关闭 thinking、手工 thinking budget 或强制 tool choice。
- Opus 5.5 价格为每百万 Token 输入 4 美元、输出 20 美元、cache read 0.20 美元。
- 不新增外部数据库、定时任务服务或桌面运行时。
- 只部署 GitHub CI 通过的精确 commit 和 GHCR digest。
- 不删除或重建生产账号、凭据、SQLite、代理绑定或配置。
