# Antigravity Manager 4.9.1 同步、Opus 5.5 与动态模型目录设计

## 目标

在保留 Lee 版定制能力的前提下，同步上游 `v4.9.1`，新增 Claude Opus 5.5 支持，并将对外暴露的模型列表改为以 Google `fetchAvailableModels` 为主数据源。新模型应自动上线，已失效模型应在 24 小时缓冲期后自动下线，不再依赖 CI/CD 修改硬编码列表。

## 不可回归的定制能力

- 单次生成请求最多尝试 6 个不同账号，即首次请求加 5 次切换；同一请求不得重用已失败账号。
- Claude、Gemini、OpenAI/Codex 协议保持相同的账号排除语义，重试耗尽时保留最后一次真实上游状态和错误。
- 保留配额保护、账号排名、周配额预留、首响应超时、代理绑定热更新与健康检查错峰。
- token 统计保留账号、原始模型、映射后计费模型、input/output/cache token、请求数和成本；详细日志关闭时仍必须写入 token 统计。
- 保留已有签名缓存恢复、定向删除账号等 Lee 版修复。

## 方案对比

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 在 Lee `main` 之上合并上游 `v4.9.1`，逐项解冲突 | 保留定制历史和现有行为，容易审计与回滚 | 24 个冲突文件需要人工判断 | **采用** |
| 以上游 `v4.9.1` 重建分支，再挑选 Lee 提交 | 基线表面更整洁 | 26 个定制提交存在遗漏或顺序依赖风险 | 不采用 |
| 仅挑选上游部分功能 | 短期冲突少 | 不能称为 4.9.1，后续同步更困难 | 不采用 |

## 上游同步设计

1. 从 Lee 当前 `main` 创建同步分支，合并精确标签 `v4.9.1`，不跟随未固定的上游分支头。
2. 冲突解决以“上游新协议与结构 + Lee 行为不变式”为原则，不整文件选择 ours/theirs。
3. 合并与动态模型功能分为独立提交，便于定位回归和单独回滚。
4. 不删除现有 SQLite 统计数据、账号 JSON、代理配置或环境变量。

## 动态模型目录

### 数据源

- 继续复用已有 `fetchAvailableModels` 调用和账号 `quota.last_updated`，不新增数据库或后台服务。
- 模型目录只汇总最近 24 小时内成功刷新的账号快照。
- 如果 24 小时内没有任何成功快照，使用最新一份历史成功快照，避免上游暂时失败导致模型列表清空。
- 一旦恢复新鲜快照，不再合并过期账号中的旧模型；因此旧模型最长在最后一次成功上报后保留 24 小时。

### 唯一列表出口

- `/v1/models`、`/v1beta/models`、Claude Models API、桌面端模型选择器和 OpenCode/Hermes/Droid/OpenClaw 等集成共用同一个后端目录结果。
- 前端 `MODEL_CONFIG` 只保留图标、分组和显示元数据，不再向模型列表无条件注入条目。
- 未知新模型继续使用现有 `inferModelGroup` 分组并直接透传，不需要前端发版。
- 用户显式配置的自定义别名仍可路由；开启 `only_raw_quota_models` 时不将别名伪装成上游原生模型。
- `deprecatedModelIds` 转发规则按当前新鲜目录对账，已不再上报的动态转发规则必须移除。

## Claude Opus 5.5

- 对外标准模型 ID 为 `claude-opus-5-5`；如 Google 目录返回不同的原生 ID，仅建立一条从标准 ID 到已发现原生 ID 的兼容映射。
- 动态目录未发现 Opus 5.5 时，默认不对普通客户端宣传可用；保留标准 ID 直接请求能力，便于使用 Ultra 账号做受控验证。
- `loadCodeAssist.paidTier` 是“付费非试用 Pro”的判定依据。账号数据增加向后兼容的付费标记，不再只保留已压缩的 `PRO` 文本。
- Opus 5.5 候选账号仅允许 Ultra，以及 `paidTier` 明确识别为付费的 Pro；试用 Pro、Free、Plus 不进入候选集。筛选后仍使用 Lee 现有排名、配额保护和 6 账号重试逻辑。
- Opus 5.5 的 adaptive thinking 始终开启。请求映射不得发送“关闭 thinking”或者与 adaptive thinking 冲突的手工 budget，并保留上游对强制 tool choice 的错误语义，不静默改写用户意图。
- token 成本表增加 Opus 5.5 的官方单价：input `$4/MTok`、output `$20/MTok`、cache read `$0.20/MTok`。上下文和输出上限优先使用上游动态元数据。

## 错误与回退语义

- 模型目录刷新失败不覆盖最后成功数据，也不触发账号禁用。
- 上游明确返回模型不存在时，终止无意义的跨账号重试；配额、鉴权或暂时错误仍按现有策略切换账号。
- 新增账号字段必须可选，旧账号文件在首次刷新前保持可读。
- 任何生产健康检查失败都使用原容器镜像和原配置回滚，不回滚或删除用户数据。

## 测试与验收

### 合并门禁

- Rust 格式化、编译和相关单元测试通过。
- TypeScript 类型检查、前端构建和 dashboard 测试通过。
- 现有账号调度测试必须证明 6 个不同账号、小账号池不重用、成功后立即停止。
- token 统计测试覆盖流式/非流式解析、cache token、原始模型/计费模型、成本聚合以及日志关闭后仍记录。

### 新功能测试

- 24 小时内新快照中的未知模型自动出现。
- 只存在于过期快照的模型在有新鲜快照后消失。
- 所有刷新失败时保留最新历史成功目录。
- 已失效的 `deprecatedModelIds` 转发规则会被移除。
- Opus 5.5 仅选中 Ultra 或明确的付费 Pro，不选中试用 Pro。
- Opus 5.5 请求不发送禁用 thinking 或手工 thinking budget，并正确统计 token 和成本。

### 生产验收

1. 记录当前容器镜像 digest、运行中 revision、配置和数据挂载，保留可验证回滚资源。
2. 服务器只部署 GitHub 上已推送且通过 CI 的精确 commit，不从未推送工作区构建。
3. 替换容器后检查 health、管理 API、`/v1/models`、账号数量、统计数据可读性与日志。
4. 使用 Ultra 账号发起一次最小 Opus 5.5 请求；如能明确识别付费 Pro，再进行一次最小 Pro 请求。真实模型请求与仅查看模型列表的结果分开报告。
5. 任一核心检查失败立即回滚到记录的原镜像，再保留失败日志进行定位。

## 非目标

- 不重写账号调度器、token 统计库或全部模型映射。
- 不新增外部数据库、定时任务服务或新依赖。
- 不修改现有账号凭据、用户 token、统计历史或代理绑定。
- 不因为模型目录动态化而删除必要的协议兼容规则。
