# 上游超时与出口配置

文本请求等待上游响应头的默认上限为 30 秒，可通过环境变量 `ABV_UPSTREAM_HEADER_TIMEOUT_SECS` 设置为 1–300 秒。超时后取消等待、移除对应代理的连接缓存，交由已有账号重试流程处理。单次请求仍最多尝试六个不同账号，额度保护和冷却规则保持不变。

文本生成在 HTTP 响应交付前同时受现有 `proxy.request_timeout` 约束，当前默认配置为 120 秒。达到总时限返回 HTTP 504 和 `upstream_response_timeout`，取消尚未交付响应的处理任务。因此持续挂起时可能在六个账号用尽前达到总时限；正常 400、429 等快速失败仍按既有六账号规则执行。已交付的流不受这一总时限截断，也不会在输出后重放请求。图像模型保留原有的较长等待时间。

Docker/Web 保存配置后会同步账号与代理绑定，并重建上游连接配置、清除旧代理连接缓存，无须仅为这些网络配置再重启服务。`request_timeout` 仍属于服务启动配置，修改总时限需重启服务。

代理池的 priority 策略仍表示优先使用优先级最高的节点，不表示均匀轮询。需要稳定且分散出口的部署，应使用账号专属绑定；公共未绑定请求可使用 round_robin。绑定数量不能超过实际可用出口数量。健康检查通过仅证明检查地址可达，仍需实际模型生成验证。

New API 的对外模型名称、渠道模型列表、映射和计费配置必须同时匹配。普通 Key 和固定渠道的管理员 Key 应分别测试：后者可能绕过常规分发且禁用外层重试，不能代替普通用户路径验证。

验证包含挂起任务取消、已交付流持续传输、真实错误状态保留，以及隔离容器中的六账号故障切换与生产生成请求。感谢上游 lbjlaq/Antigravity-Manager 及 @jeikl 提供的协议、代理池和配置基础实现。
